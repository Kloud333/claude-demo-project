# ✅ MCP Todo Example — другий, мінімальний приклад

Компактний, самодостатній приклад MCP-сервера й клієнта — окремо від
`mcp-server-demo/` (документи), навмисно **простіша тема** (todo-список),
щоб уся увага була на MCP-логіці, а не на предметній області.

## 📁 Файли (уся структура з курсу, в одному місці)

| Файл | Що це | Звідки в курсі |
|---|---|---|
| `server.js` | MCP server: 2 tools, 2 resources, 1 prompt | Defining tools / resources / prompts |
| `client.js` | **Власний клас** `TodoMCPClient` — обгортка над Client Session | Implementing a client |
| `demo.js` | Наскрізний сценарій: використовує client, щоб показати все в дії | — |

**Чому тут є окремий `client.js`, а в `mcp-server-demo/` — ні:** у першому
прикладі client-логіка не виносилась у власний клас (SDK використовувався
напряму). Тут — навмисно, точний аналог курсового `MCPClient`
(`connect()` → `session()` → `listTools()/callTool()/...`), щоб приклад
демонстрував **повну** архітектуру: наш Client клас → Client Session
(SDK) → MCP Server.

## 🧠 Що всередині — по одному реченню на кожне

- **`add_todo(text)` / `complete_todo(id)`** — tools, Claude сам вирішує, коли їх викликати
- **`todos://all`** — direct resource, весь список одразу (JSON)
- **`todos://{id}`** — templated resource, один todo за id
- **`plan_day`** — prompt **без аргументів** (на відміну від document-прикладу — показує, що параметри опціональні)

## ▶️ Запуск — 3 способи

```bash
# з кореня проєкту (claude-demo-project/), якщо ще не робив npm install
npm install
```

### Спосіб 1 — `npm run todo:demo` (найпростіше, **нуль інтерактиву**)
```bash
npm run todo:demo
```
**Нічого вводити не треба** — `demo.js` повністю автоматичний скрипт:
сам підключається, сам викликає tools/resources/prompts по черзі й
друкує результат кожного кроку в консоль. Просто запускаєш і читаєш
вивід. Найшвидший спосіб переконатись, що все реально працює.

### Спосіб 2 — MCP Inspector (візуально, руками клікаєш)
```bash
npm run todo:inspect
```
1. Перший запуск — `npx` спитає підтвердження встановлення пакету: тисни `y`
2. У терміналі з'явиться локальна URL (з токеном) — браузер відкриється сам, або скопіюй URL вручну
3. У браузері: клікни **тумблер Connect** (зверху картки сервера) — статус має стати "Connected"
4. Вкладка **Tools** → обери `add_todo` → у полі `text` введи, напр. `Buy milk` → **Run Tool**
5. Повтори для другого todo: `text = Review PR`
6. Вкладка **Resources** → `todos://all` → **Read Resource** — побачиш JSON-масив із обома todo
7. Вкладка **Resource Templates** → `get_todo` → введи `id = 1` → **Read Resource** — побачиш один конкретний todo
8. Вкладка **Prompts** → `plan_day` → **Get Prompt** (полів вводити не треба, prompt без аргументів) — побачиш готовий текст, який пішов би до Claude
9. (Опційно) Вкладка **Tools** → `complete_todo` → `id = 1` → **Run Tool**, потім знову прочитай `todos://all` — переконайся, що `done: true` з'явилось

### Спосіб 3 — реальний чат із Claude Code (найцікавіше — живий діалог)
Це вже не тестування вручну по кнопках, а справжня розмова, де **Claude сам вирішує**, що викликати.
```bash
claude
```
(запускати з кореня `claude-demo-project/` — сервер `todo-mcp` уже прописаний у `.mcp.json`)

1. Перший раз — Claude Code запитає підтвердження підключення project-scoped MCP-сервера
2. Перевір підключення командою `/mcp` — має показати `todo-mcp` як Connected
3. **Просто пиши природньою мовою**, наприклад:
   - `Додай todo: купити молоко`
   - `Які в мене зараз todos?`
   - `Познач перший todo виконаним`

   Claude сам вирішить, коли викликати `add_todo`/`complete_todo` — ти нічого спеціального не набираєш, це і є суть tools (model-controlled)
4. Друкни `/` — побачиш наш prompt як slash-команду: `/mcp__todo-mcp__plan_day` (формат завжди `/mcp__<сервер>__<prompt>`)
5. Друкни `@` — побачиш автокомпліт resources, підставиться як `@todo-mcp:todos://all`

> 💡 Якщо не хочеш возитись із Claude Code — **Способи 1 і 2 самодостатні** й нічого додаткового не потребують.

### ⚠️ Дрібні нюанси, щоб не збивали з пантелику
- Є ще `npm run todo:server` — запускає **тільки сервер**, без клієнта. Якщо запустиш його напряму, термінал "зависне" й нічого не виведе — **це нормально**: сервер чекає на stdio-клієнта, а не на людину в терміналі. Використовується під капотом в `todo:inspect`; сам по собі окремо не потрібен.
- На Windows після завершення `todo:demo` може з'явитись `Exception ignored ... I/O operation on closed pipe` — нешкідливий quirk stdio-очистки в Node на Windows, з'являється **після** того, як реальний результат уже надрукований. Безпечно ігнорувати (той самий випадок, що й у `mcp-server-demo/`).
